# Phase 1 Windows audio runner verification

The Phase 1 software gate passed on Windows x64 with the Phase 0 pinned codec
bundle and its synthetic DTS:X fixture. Both outputs used Unicode paths containing
spaces. FFmpeg and ffprobe independently identified and decoded the full streams.

| Preset | Profile | Compatible layout | Sample format | Decoded length |
| --- | --- | --- | --- | --- |
| DTS-HD MA | DTS-HD MA | 7.1 | 48 kHz, 24-bit | 96,256 samples (2.0053 s) |
| TrueHD | Dolby TrueHD + Dolby Atmos | 7.1 | 48 kHz, 24-bit | 96,256 samples (2.0053 s) |

The integration suite also checked:

- Corrupt input produced an actionable diagnostic and no output.
- A sparse test input exceeded the space estimate on the real destination
  volume and was rejected before conversion.
- A console Ctrl+Break cancelled an active decoder. Forced host exit during
  decode was recorded as interrupted on restart. Both attempts removed their
  workspaces without publishing an output.
- Existing files survived both an initial destination conflict and a conflict
  introduced during encode. A concurrent attempt in the same state directory
  was declined, and the source SHA-256 was unchanged.
- The Rust tests independently confirmed that closing a Job Object terminates
  a real grandchild process and that the disk-space error rounds up the deficit.

Run from the repository root with the Phase 0 toolchain and bundle staged, the
fixture generated by `scripts/qualify_tools.py`, and independent FFmpeg/ffprobe
on PATH:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/cargo-xfold.ps1 test --locked --offline --target x86_64-pc-windows-gnu
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/cargo-xfold.ps1 build --release --locked --offline --target x86_64-pc-windows-gnu
python scripts/test_audio_runner.py target/x86_64-pc-windows-gnu/release/xfold.exe
```

TrueHD protection is unkeyed. Receiver playback, broader DTS:X profile
coverage, and clean Windows installation remain unverified.
